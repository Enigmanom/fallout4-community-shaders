# Upscaling

Consumer: sampler-bias targets (`SAMPLER_MIP_BIAS`) only; the SSLR chain uses stock shaders.
Upscaling, FrameGeneration and MotionVectorFixes are maintained in-house; these comparisons describe
main's existing implementation, not an upstream-conversion plan or parity claim. The FO4 shader copies
(`EncodeTexturesCS`, `DepthRefractionUpscalePS`, `UpscaleVS` under `FO4/Upscaling`), settings keys, SDK
inputs, render scheduling and presentation are retained.

## Differences from pinned upstream

| Kind | Upstream | Fallout 4 | Why | Where |
|---|---|---|---|---|
| Forced | FrameBuffer-adjusted current/previous samples in ISReflectionsRayTracing | Unchanged upstream b4 current-frame clamp; no dynamic-resolution adjustment in the shader because the chain runs in the SSLR proxy pass below | FO4 has no previous-frame reflection sample, and Hi-Z integer loads index the engine's top-left region pyramid | `SharedData.cpp`, `UpscalingAnchors.h` |
| Forced | Stock SSLR chain runs against full-extent targets | Prepass, Raytracing, BlurH and BlurV run in one full-proxy pass (render-resolution proxies, ratio 1, whole-proxy viewport); ray result and BlurV are copied back for water and the composite | Under dynamic resolution the stock quad spans [0, ratio] and the ray pass rescaled TexCoord again, so reflections slid under camera rotation; stock shaders are valid once TexCoord spans [0, 1] | `DynamicResolution.{h,cpp}` `BeginProxyPass`, `TemporalRenderHooks.cpp` |
| Forced | Single non-inverted perspective depth | FO4 native scene DSV combines first-person and world projections (near depth ≤0.01 and world `mad(d,1.01,-0.01)` use different inverses) | engine-facts Native composite depth partition | `Engine.h`, `FO4/Depth.hlsli` |
| Pending | World-projection SDK depth (SR and FG) | The SR encoder and FG copy native partitioned depth into typed shared R32_FLOAT with inactive pixels padded to sky=1; neither consumes the substrate's canonical t17 depth | Typed storage does not reconcile projection partitions; not shown to be engine-impossible | `TemporalResolve.cpp`, `TemporalFrameGenerationInputs.cpp`, `EncodeTexturesCS.hlsl` |
| Forced | Depth/refraction fullscreen resolve with SAOCameraZ MRT1 | FO4 copy samples native depth/refraction normals with shared DR/jitter math and writes RefractionNormals plus SV_Depth, without SAOCameraZ | Native post-processing consumes the scene DSV and FO4 has no SAOCameraZ attachment | `DepthRefractionUpscalePS.hlsl` |
| Forced | Shaders add `SharedData::MipBias`; engine samplers are never biased | `SamplerBias` swaps the anisotropic engine samplers for `MipLODBias = MipBias` copies around `DrawWorld::DeferredPrePass` and `Forward`. `SAMPLER_MIP_BIAS` resolves the shader-visible `MipBias` to 0, so upstream `SampleBias(..., MipBias)` and Terrain Variation's `SampleLevel` land at upstream's lod + MipBias instead of twice that. Injected (contributor `UpscalingSamplerBias`, only while Upscaling is loaded) on every reconstructed shader drawn inside either window: `kDeferredPrepass`, `kDistantTree`, `kEffect`. Gap: the override biases only `D3D11_FILTER_ANISOTROPIC` samplers, so a non-anisotropic sampler loses the bias upstream would give it | The swap cannot be dropped per window, and an uncompiled prepass variant draws stock bytecode with no shader-side bias; per-draw sampler switching would need the lazy sampler-bind path reversed | `FO4ShaderData.hlsli`, `ShaderDefines.h`, `SamplerBias.cpp` |
| Forced | Jitter and dynamic-resolution publication into the Skyrim viewport | Equivalent offsets and RenderTargetManager ratios are published after FO4's native `UpdateTemporalData`, preserving top-left active-region proxies | FO4's state/target-manager layout and native updater differ | `TemporalRenderer.cpp`, `DynamicResolution.cpp` |
| Forced | Menus and offscreen cameras render after upscaling | Pip-Boy-target Interface3D renderers (item preview, Pip-Boy screen) and the companion local-map callback run in an `UnscaledRenderScope` (ratios 1/1, jitter zero, restored on exit), vendor upscalers only; auxiliary offscreen cameras (precipitation, facegen) take `dynamicResolutionLock = 1`. The scope applies only when the renderer targets logical 60/61; barter/container/workbench renderers draw full-frame targets 63/64 composited before the upscale, so they stay scaled and jittered. Native TAA is unaffected | `DrawWorld::Render_UI` calls these callbacks while render scale is live and scales their default viewports; a callback-wide scope would stretch the full-frame composite 1.5x | `Engine.h` `UnscaledRenderScope`, `TemporalRenderHooks.cpp` |
| Divergence | Pre-tonemap SR with upstream exposure/HDR policy | Post-tonemap/LUT gamma-2.2 R8G8B8A8_UNORM SR and automatic exposure | Main's explicit color contract; no engine evidence proves pre-tonemap integration impossible | `TemporalResolve.cpp` |
| Divergence | Direct upstream FidelityFX FSR3 dispatch | Streamline FSR3/FSR4 D3D12 providers and typed shared input transport; FO4's encoder writes undilated motion to u2 for FSR (upstream binds u2 only for DLSS). The shared `FidelityFX.{h,cpp}` is not consumed | In-house SDK/backend architecture | `Streamline.cpp`, `SuperResolutionProviders.cpp`, `EncodeTexturesCS.hlsl` |
| Divergence | FSR quality ratio used for all providers | SDK render-size queries, quality values 0–4 and provider-specific sizing; upstream jitter phase/sequence and projection signs are retained | Upstream uses `ffxFsr3GetUpscaleRatioFromQualityMode`; FO4 queries DLSS/FSR optimal extents | `TemporalRenderer.cpp` `PrepareRenderSize`, `Streamline.cpp` |
| Tweak | Upstream provider selection and `upscaleMethodNoDLSS` preference | FSR4 is included in the method values and one SR preference is persisted | Provider preference presentation | `TemporalRenderSettings.h` |
| Divergence | RCAS D3D11 dispatch | D3D12 RCAS on SDR output; the shader is unchanged and the sharpness exp2 math matches | In-house backend and color stage | `RCAS/RCAS.cpp` |
| Tweak | Upstream DLSS GPU/model preset defaults | Main's explicit/nondefault DLSS preset policy alongside RCAS controls | Preset defaults, not a different sharpening algorithm | `Streamline.cpp` |
| Pending | Production reactive/transparency masks from TAA xy and water normal.z | The encoder keeps `taa.x * 0.1 + taa.y` and normal.z math, but null t0 and FO4's two-channel normal input yield zero masks | Production mask inputs are not ported; not shown to be engine-impossible | `EncodeTexturesCS.hlsl` |
| Pending | Underwater-mask upscale and water consumer chain | Main's depth/refraction publication and linear-depth regeneration, without `UnderwaterMaskUpscalePS.hlsl` | Equivalent underwater producer/consumer coverage is not ported | `DynamicResolution.cpp`, `TemporalResolve.cpp` |
